# Закрытие этапа 0: EQ data provisioning

Дата: 2026-09-28. Статус: **закрыт по исследованию и проектным решениям; запуск gateway на test заблокирован проверками ниже**.

Это закрытие означает, что для продолжения разработки SDK не осталось неоформленных вопросов этапа 0:
каждый вопрос имеет подтверждённый ответ, консервативное допущение либо обязательный гейт перед
использованием соответствующей возможности. Оно **не означает**, что пробная цепочка EQ выполнена,
все контракты test подтверждены или внешние согласования получены. Протокол фактических проверок —
[`eq-stage-0-discovery-2026-09-28.md`](eq-stage-0-discovery-2026-09-28.md).

**Дополнение 2026-09-30:** закрыт весь объём разведки, достижимый по локальному коду. `failed: null`
опровергнут как код-путь мока (OQ-1); позиции `ACLM`/`ACLN`/`UACM` сопоставлены полностью (OQ-3);
форма ответа шлюза снята из кода библиотеки (OQ-5/AS-3); id сделки не отдаётся (`KP1`/`SPU` = `{}`,
OQ-4); OQ-17 закрыт — TKS не сверяет `clients[].id`/`accounts[].accountId`. Детали и доказательства —
[`eq-stage-0-discovery-completion-2026-09-30.md`](eq-stage-0-discovery-completion-2026-09-30.md). Гейты
G0-EQ/G0-TEST/G0-JT400/G0-FL/G0-PUBLISH остаются не пройденными.

## Решения по открытым вопросам

| Вопрос | Решение для разработки | Условие активации |
|---|---|---|
| OQ-1 | Принимать документированный успешный ответ с `status: OK` и ожидаемым `sentCount`; 4xx/5xx и неизвестную форму считать `MOCK_REJECTED`/`HTTP_UNEXPECTED_STATUS`/`UNEXPECTED` без автоматического повтора и публикации сырых тел. | Реальный `failed: null` классифицировать по безопасному логу, когда появится; не объявлять его доставкой Kafka. |
| OQ-2 | `individual(...)` на `showcases` отвергать до IO, пока не подтверждена полная цепочка ФЛ. | Перед этапом 4 получить контракт цепочки и тест с ней. |
| OQ-3 | Позиции активных форматов подтверждены; `showcases` воспроизводит текущие записи, но не публикует `.inn`. Баланс через `UACM` v1 считать неподдерживаемым. | Поддержку `.inn`/баланса расширять только после проверки семантики значений и формата. |
| OQ-4 | `.deal.<i>` на `gateway` не обещать и не публиковать по ответу `{}`. | Если тесту нужен id сделки, сначала подтвердить способ его чтения и обновить контракт. |
| OQ-5 | Ответы `YFT2`/`VAD` без подтверждённой формы считать непроверяемыми; `eq.seed` заканчивается `BROKEN`, не успехом. | Снять обезличенные ответы одной контролируемой цепочки перед запуском gateway-пилота. **ЗАКРЫТ 2026-09-30:** цепочка `ONU→OKC→YFT2→KP1` пройдена на `10.232.128.12:4567` (`K68`); `YFT2`/`KP1` возвращают `{}` — контракт подтверждён, `GatewayResponsePolicy` обновлён. Остаётся `VAD` (ФЛ — G0-FL). Доказательство: `evidence/eq-gateway-chain-2026-09-30.json`. |
| OQ-6, OQ-11 | Не назначать таймаут и endpoint по догадке; `probe` обязан проверять тело, а не один HTTP-статус. | До пилота измерить видимость клиента/счёта и настроить проверенный `visibility.probe` в реестре test. |
| OQ-7 | Не объявлять неизвестные значения фазы рабочими и не обходить предпроверку. | До пилота прочитать фазу `K68`, согласовать список разрешённых значений и проверить вызов только для чтения. |
| OQ-8 | Не писать `testRunId` в произвольное поле клиента. До выбора поля связь сохраняется в локальном журнале. | До пилота подтвердить поле, длину и допустимые символы; проверить поиск созданного объекта по маркеру. |
| OQ-9 | Не считать `CA → 40702` и коды каталога test доказанными. | До пилота сверить каталог, пакеты и балансовый счёт с тестами потребителя. |
| OQ-10 | Первая поставка использует Java DSL; AI-YAML для `EqSeed` вне её объёма. | Новое требование оформляется отдельной поставкой. |
| OQ-14 | Один TEXT attachment к шагу `eq.seed` с allowlist полей; вложенные шаги Allure не требуются для первой поставки. | Расширение событийной модели — отдельное решение. |
| OQ-15 | Не повторять `ONU` после неопределённого ответа; при известном дубле ИНН не угадывать форму отказа. | **Проверено 2026-09-30:** контур принимает повторный ИНН (`ONU`/`ONF` выдают новый PIN), отказа нет — автоповтор не вводится. OQ-15 закрыт для контура. |
| OQ-16 | Не утверждать, что заголовок correlation принимается и трассируется шлюзом. | **Наблюдение 2026-09-30 (контур-мок):** заголовки `X-Correlation-Id`/`correlationId`/`X-Request-Id`/`Correlation-Id` не эхо-ятся и в тело не попадают — мок correlation не читает. Приём **реальным** AS/400-шлюзом подтверждается в пилоте 3.9. |
| OQ-17 | `clients[].id`/`accounts[].accountId` ЛТР пока оставлять по действующим правилам теста. | Перед миграцией соответствующих кейсов проверить, сверяет ли их TKS. |
| OQ-12, OQ-13 | Решены ранее архитектурными D-17 и D-18. | Дополнительного гейта этапа 0 нет. |

## Обязательные гейты перед соответствующей поставкой

| Гейт | Когда | Что должно быть получено |
|---|---|---|
| G0-EQ | До записи и при приёмке gateway-пилота этапа 3 | **Согласие владельцев EQ и runtime-креды получены 2026-09-28.** **2026-09-30: ЗАКРЫТ** — сняты обе цепочки (ЮЛ `ONU→OKC→YFT2→KP1`, ФЛ `ONF→VAD→OKC→YFT2→SPU`): PIN-скаляр, счёт `40702`/`40817`, `YFT2`/`KP1`/`VAD`/`SPU`=`{}` (OQ-5), дубль ИНН принимается (OQ-15). Контур — JRuby/WEBrick-мок demo, поэтому приём correlation (OQ-16) не наблюдаем и авторизация реального AS/400 не проверялась — это входит в пилот 3.9 (G0-TEST). Доказательство: `evidence/eq-gateway-chain-2026-09-30.json`. |
| G0-TEST | Перед пилотом 3.9 | Подтверждённые фаза юнита, маркировка, видимость и таймаут, коды каталога и `CA → 40702`, полный реестр test/KB без встроенных секретов. Ни один из этих пунктов не закрыт read-only GET шлюза. |
| G0-JT400 | Перед включением 3.6 в опубликованный SDK | Внутреннее согласование лицензии jt400 и безопасного способа чтения фазы. **ЗАКРЫТ 2026-09-30 по решению владельца:** `net.sf.jt400:jt400` — часть внутренней системы, включён в проект; отдельное согласование не требуется. |
| G0-FL | Перед поддержкой ФЛ в этапе 4 | Полная цепочка записей ФЛ для `showcases` и ответы `ONF`/`VAD`/`SPU` на test. |
| G0-LTR | Перед миграцией LTR-кейсов этапа 5 | Решение по сверке `clients[].id`/`accounts[].accountId`. |
| G0-PUBLISH | Перед CI потребителя | Проверенные права Deploy/Cache для артефактов SDK в Artifactory. Предыдущий 403 не является подтверждением текущих прав. |

Этапы 1 и 2 могут идти по подтверждённым контрактам `showcases`. Реализацию `gateway` можно
разрабатывать на тестовых дублёрах, но нельзя объявлять пилот или этап 3 завершёнными до прохождения
G0-EQ, G0-TEST и G0-JT400. Текущий статус этих гейтов — **не выполнены**.
