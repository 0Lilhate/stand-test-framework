Семь пунктов ниже. Для каждого — точный вопрос и тип доказательства.

### 2.1 Фаза юнита (OQ-7)
- **Вопрос:** какие значения фазы юнита считаются рабочими? Какое значение у юнита probe/test?
- **Как получить:** прочитать фазу вызовом `MONUNTSTS` (parm0 = юнит, выход 4 символа) для целевого
  юнита. SDK-сторона готова (`UnitPhaseGate`, `GatewayConfigParser`).
- **Нужно для:** `unit-phase.allowed` в реестре test; иначе каждый сценарий падает на `prepare`.
- **Зависимость:** AS/400 test — `unit-phase.system-ref`.

### 2.2 Маркировка `testRunId` (OQ-8)
- **Вопрос:** в каком поле клиента можно писать маркер, какова максимальная длина и допустимый алфавит
  (для ФЛ ФИО без цифр)?
- **Сейчас:** маркер идёт только в имя (`name-prefix + PIN`) и в журнал; в поле клиента не пишется.
- **Нужно для:** `BR-42` (поиск созданного объекта по маркеру).

### 2.3 Видимость клиента и счёта (OQ-6, OQ-11)
- **Вопрос:** медиана и максимум задержки видимости клиента/счёта в TKS на test; какой endpoint
  надёжно показывает наличие (endpoint TKS или сама витрина)?
- **Нужно для:** `visibility.probe` (endpoint ID, query, `expect-status`, `expect-body`, таймаут по
  максимуму + запас). Проба обязана проверять **тело**, не только HTTP-статус.

### 2.4 Каталог и `CA → 40702` (OQ-9, R-10, DEP-7)
- **Вопрос:** отличаются ли коды пакетов/типов счетов между ift и test; даёт ли тип `CA` балансовый
  `40702` на test? Подтвердить рабочие коды (`NZCR`→отделение, `PU_NWA`, `SP_FastDevelopment`, услуги
  `4.14.x` — это IFT-значения потребителя, в TKS их нет).
- **Нужно для:** `defaults` реестра test и корректности балансового счёта.

### 2.5 Параметры стенда (0.12, DEP-3/DEP-5)
- **Вопрос:** адрес шлюза test, юнит, отделение, кассы по валютам (RUR/USD/EUR), регион и коды ИФНС;
  адреса и **имена** учёток `pk`, `tks`, `prodcat`, `prodprofile_u`, Kafka, UI.
- **Формат:** только имена переменных; значения — через environment.
- **Нужно для:** реестра test / KB (`environments/test.yml`) и `eq-backends.eq` с `kind: gateway`.

### 2.6 Полный реестр test
- **Нужно:** полный реестр test **без встроенных секретов** — поля без умолчания как `*-ref`,
  секреты только `*-ref` (BR-46), `write-allowed: true`, кассы по валютам, таймауты
  (`connect 10s`, `response` по замеру), `serialization.acquire-timeout`.

### 2.7 Эксплуатационное условие пилота (AC-8, NFR-07)

## 5. G0-PUBLISH — права Artifactory

**Статус артефактов (проверено 2026-09-30):** `./gradlew publishToMavenLocal` зелёный; в
`~/.m2/repository/ru/alfa/stand/test/` — **15 модулей** (14 SDK + `bom`), включая новые
`stand-test-eq` и `stand-test-http` (в каждом: `.jar` + `-sources` + `-javadoc` + `.pom` + `.module`).
У `stand-test-http` **нет** `-test-fixtures.jar` — исключение вариантов (1.3.1) работает; устаревший
файл от прежней публикации удаляется чистой публикацией.

**Осталось (внешний блокер):**

- **Что нужно:** подтверждённые права Deploy/Cache на **локальный** репозиторий для
  `ru/alfa/stand/test/**` и креды в runtime environment.
- **Проверка:**
  ```bash
  export ARTIFACTORY_HOST=https://binary.alfabank.ru
  export LIBRARY_SNAPSHOT_REPOSITORY=<repo> LIBRARY_RELEASE_REPOSITORY=<repo>
  export ARTIFACTORY_USER=<user>; read -rs ARTIFACTORY_PASSWORD && export ARTIFACTORY_PASSWORD
  ./gradlew publish --console=plain            # env, НЕ -P
  ```
- **Различить 401/403 заранее:** `curl -u user:pass` на любой Artifactory API-endpoint — `401` = логин
  не принят, `403` = логин ок, а прав Deploy на репозитории/пути нет. При `403` ничего не пишется.
- **Целевой адрес** — локальный репозиторий (агрегат `.../artifactory/public/` PUT не принимает).
  Подробности — `docs/publishing.md`.
- **Замечание среды (2026-09-30):** в текущем процессе `ARTIFACTORY_*` не заданы (в `~/.gradle` лежат
  чужие креды, автоматически не применялись). Публикацию выполняет CI/оператор с правами.
- **Зависимость:** `stand-test-eq` и `stand-test-http` не опубликованы удалённо; CI потребителя
  собирается только на `mavenLocal()`. Версия — ветве-квалифицированная
  (`0.1.0-target.solution-SNAPSHOT`, `./gradlew printVersion`).
