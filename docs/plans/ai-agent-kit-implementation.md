# План реализации — кит для AI-агента (`docs/ai-agent/`)

## Контекст / цель

Цель — писать автотесты через агента по текстовому описанию тест-кейса, чтобы база знаний и скиллы
развивались сами, и чтобы этим было удобно пользоваться. Исполнитель — подписочный хост (Claude Code
или opencode), а не собственный рантайм: попытка построить его (четыре Gradle-модуля
`stand-test-agent-*`, ~31 500 строк) была ошибочным направлением и удалена коммитом `8c3a342`.
Возвращаться к ней не следует — хост уже даёт цикл, вызов инструментов, разрешения и субагентов.

Кит декларативен: 17 скиллов, 13 команд, 2 авто-загружаемых правила, 2 workflow-документа, контракт
базы знаний из 20 JSON-схем, две синхронные копии (`.claude/` и `.opencode/`), копируемые в
проекты-потребители; сверх них в Claude-копии — слой энфорсмента (`hooks/`) и 3 субагента.
Его слабое место было одно и общее: **пайплайн из 11 стадий держался на том, что модель прочитала
инструкцию и решила ей следовать.** План закрывает это слоями, которые исполняет хост.

Источник истины по контрактам SDK — `docs/arch/stand-test-sdk-implementation-plan.md`. Находки по
самому киту — `docs/agent-analysis/current-state-analysis.md` (A-01…A-17).

| Субагенты — этап 4 | `28e85cb` | стадии 2/4 (`stand-test-kb-resolver`), 8 (`stand-test-safety-reviewer`), 11 (`stand-test-quality-reviewer`); у ревьюеров нет Write — найденное они не чинят; на вход safety-ревью идут пути артефактов и дизайн, **не транскрипт авторинга**; quality-ревью читает исходный текст кейса, а не дизайн. `SubagentStop` + проверка в `record-gate`: `PASS` не пишется, пока после последней правки артефакта не завершился субагент. `AgentDefinitionSafetyTest` |

Ключевые свойства, на которые опирается остальное:

- **Гейт привязан к хешу содержимого.** Правка после ревью снимает покрытие автоматически.
- **`record-gate` не верит вердикту**: детерминированная половина проверок перезапускается, `PASS`
  поверх блокирующей находки не записывается. Вердикт обязан называть файлы и покрывает ровно их —
  вызов без списка отвергается, иначе перезапускать было бы нечего, и именно так эта проверка
  однажды и не работала.
- **Журнал прогонов уже пишется** (`.claude/.stand-test/run-journal.jsonl`) — хуком, ни одной
  LLM-записи. Это фундамент цикла обучения, и он копит данные с первого дня. Одна запись = одно
  реальное появление падения: результат читается один раз по паре путь+mtime, иначе порог «отпечаток
  встречался ≥2 раз» выполнялся бы перечитыванием одного и того же XML. Копится только то, что
  запущено через агента: прогон из IDE или своего терминала хук не видит.
- **Курируемую KB пишут под пермитом, а не запретом.** Запрет, который нельзя удовлетворить, — это не
  энфорсмент: шаг просто уходит из-под инструмента. Ни один из трёх слоёв не претендует на силу
  соседнего, и в коде это записано прямо: пермит модель выдаёт себе сама, неподделываемая часть —
  подтверждение хоста и повторное чтение того, что легло.
- **Делегирование доказуемо, содержание ревью — нет.** `SubagentStop` даёт хуку ровно один факт: после
  записи артефакта завершился какой-то субагент. Какой именно, прочитал ли он артефакт и передали ли
  его вердикт без правок — хук не знает и знать не может. Закрыт конкретный обход: контекст, писавший
  код, не подписывает сам себя.
- **Незаявленный вход Gradle — это проверка, которая молча не выполняется.** Весь кит объявлен
  входом тестов `stand-test-ai-schema` после того, как два зонда прошли впустую именно из-за этого.

### Цикл обучения сигнатурам — как не дать агенту писать догадки

Приём тот же двухслойный, что уже отработал на KB: **разделить наблюдение и знание.**

| Слой | Что | Кто пишет |
|---|---|---|
| Журнал | `.claude/.stand-test/run-journal.jsonl`, append-only. Источники — JUnit XML, код возврата gradle, `git diff --stat` | **только хук** — уже работает |
| Отпечаток | детерминированная нормализация: UUID, `testRunId`, таймстампы, hex, числа, пути → токены | машина — уже работает |
| Реестр | `hooks/signatures.json` — машиночитаемый двойник таблицы §Step 3 из `stand-test-debugging/SKILL.md` | курируется |
| Кандидаты | сигнатура предлагается **только** если отпечаток встречался ≥2 раз **и** в журнале есть `fail → правка → pass` того же класса. Уверенность выводится механически | предлагает агент, промоутит человек |

**Механический анти-догадочный замок:** `messagePattern` кандидата обязан быть **выведен** из
нормализованного сообщения — скрипт применения отвергает паттерн, который не матчит сырые сообщения
**всех** процитированных записей журнала. Расширить паттерн до догадки нельзя: под него должны
подойти доказательства.

## Риски

| Риск | Влияние | Что делаем |
|---|---|---|
| **Ложная находка дороже пропущенной** | Высокое: гейт, который всегда красный, выключают, и вместе с ним перестают работать точные находки | Корпусный прогон по всем семи `valid/*.json` и шести фикстурам обязан оставаться зелёным; эвристики не блокируют. Один раз риск реализовался не в точности находок, а в бухгалтерии Stop-гейта (`c16b09d`): держать сессию — тоже способ быть всегда красным |
| **Тест проверяет замысел автора, а не написанное** | Высокое: три раза за две сессии зонд находил дыру не в коде, а в проверке | Каждое новое правило **ронять зондом**; сверять количества, а не множества |
| Незаявленный вход Gradle | Среднее: проверка молча не выполняется | Весь кит — вход тестов; при добавлении путей обновлять `inputs.files` |
| Расхождение политики двух хостов | Среднее: оба бандла на месте, оба теста зелёные, один хост может править `checkstyle.xml` | `ClaudeSettingsSafetyTest` сверяет семантически; `BundleParityTest` файлы этих двух конфигов не видит по построению |
| Поток `HIGH`, который перестанут читать | Среднее | Эвристик три, а не пятнадцать; каждая с конкретным `fix`; `HEURISTIC` отличает их от доказанных прямо в отчёте |
| Сканирование подстрок вместо AST (находки 8, 9, 12, 17) | Среднее: сито, а не периметр | На декларативном треке нарушения непредставимы схемой; для Java-трека нужна приёмка на реальном корпусе |

## Верификация

```bash
./gradlew --no-configuration-cache build                  # вся сборка, включая тесты кита

# слой энфорсмента
node docs/ai-agent/.claude/hooks/stand-guard.mjs scan <файл> --json
./gradlew :stand-test-ai-schema:test --tests '*GuardrailScanner*'
./gradlew :stand-test-ai-schema:test --tests '*ClaudeSettings*'
./gradlew :stand-test-ai-schema:test --tests '*BundleParity*'
./gradlew :stand-test-ai-schema:test --tests '*GuardGateRecording*'   # гейт, делегирование
./gradlew :stand-test-ai-schema:test --tests '*GuardRunJournal*'      # журнал прогонов
./gradlew :stand-test-ai-schema:test --tests '*AgentDefinition*'      # у ревьюеров нет Write
node docs/ai-agent/.claude/hooks/stand-guard.mjs kb-status            # запускать в проекте-потребителе
node docs/ai-agent/.claude/hooks/stand-guard.mjs kb-validate --exit-code
node docs/ai-agent/.claude/hooks/stand-guard.mjs alias-check
```

**Сквозная проверка на живом кейсе** (в репозитории-потребителе): установить кит, выполнить
`/stand-test-bootstrap-kb --from-registry`, затем `/stand-test-generate-java-test` на реальном
текстовом кейсе. Ожидается: **алиасы** резолвятся без блокирующих вопросов (реестр их
свидетельствует), а недостающие контрактные детали их по-прежнему вызывают — и это правильный
результат, а не регресс: их не свидетельствует ни один реестр, и заполняются они через
`/stand-test-kb-update` из настоящих источников. Дальше: попытка записать тест с `Thread.sleep`
отвергается в момент записи; safety-review выполняет субагент без Write, а `record-gate` не примет
`PASS`, если субагент не завершался после записи артефакта; `./gradlew test` со skip-гейтом даёт
предупреждение о `skipped` в любом модуле; попытка закончить сессию с непроверенным исполняемым
артефактом блокируется, а написанный по дороге отчёт её не держит.
