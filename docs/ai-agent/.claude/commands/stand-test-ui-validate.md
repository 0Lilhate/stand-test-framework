# /stand-test-ui-validate — the gates and the report

Stages 7–9 of the UI branch. Nothing generated by this branch reaches a human without it.

## Input

The generated test class(es) and Page Objects, `UiCase.md` (and the original case text),
`UiCaseCompleteness.md`, `UiDiscoveryReport.md`, `UiScenarioDesign.md`, any registry addition, the
build diff.

## Output

- UI safety review report (protocol template + the UI gate table).
- `UiTestReview.md` — the quality verdict.
- `ui-generation/<scenario-id>/UiGenerationReport.md` + `original/` + `original.sha256`.
- A `READY` / `NOT-READY` recommendation.

## Steps

1. **UI safety review, in a separate context** —
   [`stand-test-ui-safety-review`](../skills/stand-test-ui-safety-review/SKILL.md) via the
   `stand-test-safety-reviewer` subagent (no `Write`: it reports findings, it does not fix them). It
   is given the artifact **paths**, not the authoring transcript — a context reviewing its own
   transcript reviews its intent.
   Run the protocol [`stand-test-safety-review`](../skills/stand-test-safety-review/SKILL.md)
   alongside it for everything not UI-specific (the Java, the registry addition, the backend steps).
   **Any BLOCK ⇒ regenerate.** Never hand-patch around a guardrail, never weaken the check that
   caught it.
2. **Record the verdict** — from the *calling* context, naming exactly the files it covers:
   `node <bundle>/hooks/stand-guard.mjs record-gate --gate safety-review --verdict PASS <files>`.
   `record-gate` re-runs the deterministic half and refuses a `PASS` over a blocking finding, and
   refuses one when no subagent has finished since the artifact was last written. Editing an artifact
   after its review drops the coverage automatically — the record binds to the content hash.
3. **Compile and run gate** — `./gradlew compileTestJava checkstyleTest`; then the test itself when a
   stand is configured. Read `build/test-results/test/TEST-*.xml`, not the exit code, and write down
   what it said: `skipped="1"` means the environment gate fired and no browser was opened.
4. **UI quality review, in a separate context** —
   [`stand-test-ui-quality-review`](../skills/stand-test-ui-quality-review/SKILL.md) via the
   `stand-test-quality-reviewer` subagent, which is given **the original case**, not the design. A
   check lost in the design is invisible to a review conducted against the design.
   `REWORK` re-enters at stage 6, 5, 4 or 3 — the verdict says which.
5. **Generation report** —
   [`stand-test-ui-generation-report`](../skills/stand-test-ui-generation-report/SKILL.md). Eight
   sections: covered · not covered and why · assumptions · fragile locators · the UI↔backend binding ·
   gate results · files created · the original generation.
6. **Preserve the original generation** — copy each generated file into
   `ui-generation/<scenario-id>/original/` **with the Write tool** (never `cp`, `cat >`, `tee` or
   `sed -i`: the guard refuses a file written by the shell, and that route bypasses the scanner and
   the artifact registry), hash them, and write `original.sha256`. Without this base KPI-4 is
   unobservable.
7. **Record the case → test link** in `knowledge-base/mappings/`, as the protocol branch requires, so
   the generation is traceable to the case that asked for it.

## Readiness criteria

`READY` requires all of:

- [ ] UI safety review `PASS` or `PASS-WITH-NOTES`, recorded with `record-gate`.
- [ ] Protocol safety review `PASS` or `PASS-WITH-NOTES`.
- [ ] UI quality review `APPROVE` or `APPROVE-WITH-NOTES`; **zero dropped expectations**.
- [ ] Test and Page Objects compile and pass checkstyle.
- [ ] Test executed against a stand, **or** the report states plainly that it was not and why.
- [ ] Generation report complete in all eight sections.
- [ ] `original/` and `original.sha256` present and consistent.
- [ ] Case → test mapping recorded.

Anything else is `NOT-READY`, and saying so is the point: `READY` claimed over an unrun gate spends
the reviewer's trust on an unverified artifact, which is worse than an honest `NOT-READY`.

## Human approval points (blocking)

1. **Registry additions** proposed by discovery — sign-in locators, a `discovery-account-ref`, a new
   alias. Proposed by the run, applied by a human.
2. **The merge**, on the generation report. This command recommends; it never merges.
