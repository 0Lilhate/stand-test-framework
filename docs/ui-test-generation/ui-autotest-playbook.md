# UI-автотесты: команды агента

Шпаргалка. Команды работают в **проекте-потребителе**, где установлен кит (в этом репозитории он —
исходник, `docs/ai-agent/`).

Установка, один раз:

```bash
node docs/ai-agent/install.mjs --target <consumer-repo>            # для Claude Code
node docs/ai-agent/install.mjs --target <consumer-repo> --host opencode
```

---

## 1. Обновить базу знаний

```
/stand-test-kb-update <путь к OpenAPI | AsyncAPI | .proto | SQL | application.yml>
```

Пример:

```
/stand-test-kb-update specs/tks-client-pckg-v10.yaml
```

Агент разберёт спеку, покажет diff (added / updated / unchanged / conflicts) и запишет в
`knowledge-base/` после подтверждения. Ничего не удаляет и молча не перезаписывает. Dry-run по умолчанию.

**Неструктурированный документ (ФС, ТЗ, BRD, PDF, DOCX) — три шага:**

```
/stand-test-ingest-spec docs/ФС-Такса-v3.docx      # → knowledge-base/candidates/<id>/
/stand-test-review-kb-candidates <id>              # отчёт: что применимо, что спорно
/stand-test-apply-kb-candidates <id>               # перенос одобренного в базу
```

> **Про UI.** В схеме базы знаний UI-сущностей (экраны, локаторы) **нет** — это открытая задача S-5.3,
> поэтому `/stand-test-kb-update` для экранов не применяется. Из UI в базу пишется только связка
> «кейс → тест» в `knowledge-base/mappings/`, и её создаёт сама генерация на девятой стадии.
> Локаторы живут в Page Object, фактура экранов — в отчёте разведки.

## 2. Сгенерировать UI-тест

```
/stand-test-generate-ui-test <описание кейса или путь к файлу с ним>
```

Пример:

```
/stand-test-generate-ui-test "Приложение taksa, окружение ift, роль admin.
Администратор входит в систему, открывает раздел «Продуктовый каталог»
и видит список продуктов. Ничего не создаёт и не меняет."
```

Агент пройдёт девять стадий и вернёт: `UiCase.md`, `UiDiscoveryReport.md`, `UiScenarioDesign.md`,
Page Object, JUnit-тест, отчёты безопасности и качества, `UiGenerationReport.md` + снимок исходной
выдачи, запись в `mappings/`.

Остановится и спросит, если: в кейсе не хватает блокирующего (стадия 2), нужен новый алиас в реестре,
сценарий меняет деловые данные, либо дело дошло до merge.

## 3. Разведка: агент смотрит UI сам

Отдельной командой, до генерации:

```
/stand-test-ui-discover <алиас приложения> <что посмотреть>
```

Пример:

```
/stand-test-ui-discover taksa "витрина разделов после входа и экран продуктового каталога"
```

Агент откроет приложение в браузере **под учётной записью разведки**, снимет каждый элемент со всеми
доступными ступенями локатора, процитирует тексты дословно и перечислит неисследованные экраны →
`UiDiscoveryReport.md`. Необратимых действий не выполняет.

**Если учётной записи разведки нет** — два рабочих обхода:

| Обход | Как |
|---|---|
| Показать разметку | открыть экран самому и отдать агенту HTML нужного блока — он снимет локаторы из него |
| Через артефакт падения | попросить шаг ожидания несуществующего элемента: упавший шаг положит **скриншот** экрана в `build/stand-test-ui/`, агент прочитает его и подберёт локаторы |

Административную учётную запись в разведку подставлять нельзя (SEC-10): кнопку с необратимым
действием нельзя распознать до клика.

## 4. Узкие команды

| Команда | Что делает |
|---|---|
| `/stand-test-ui-design <кейс>` | только дизайн сценария: шаги, проверки, ожидания, корреляция |
| `/stand-test-ui-java <дизайн>` | только Page Object + JUnit-тест |
| `/stand-test-ui-validate <тест>` | только гейты безопасности и качества |
| `/stand-test-debug <вывод упавшего теста>` | разбор падения: причина, класс ошибки, что чинить |
| `/stand-test-generate-env` | реестр окружений из базы знаний |
| `/stand-test-kit-doctor` | проверка, что кит установлен целиком |

Узкая команда не отменяет предыдущие стадии — она выполняет их срез.

---

## 5. Запуск теста

```bash
./gradlew test --tests '*ВашТест'                              # обычный прогон
./gradlew test --tests '*ВашТест' -Dstand.test.ui.headless=false   # с видимым браузером
```

Один раз на машину: `./gradlew :stand-test-ui:installPlaywrightBrowsers`.

После прогона смотреть `build/test-results/test/TEST-*.xml`: `skipped="1"` — браузер не открывался,
зелёное ничего не доказывает.

Упавший шаг оставляет в `build/stand-test-ui/`: скриншот, консоль, сетевую историю, а при
`trace: on-failure` — трейс для Playwright Trace Viewer.

| Что | От кого |

| отдельная учётная запись разведки (без прав на необратимые операции) | владелец приложения |
| пять локаторов формы входа + элемент, видимый только после входа | снимается с экрана |
| доверие к внутреннему CA на машине прогона | администратор рабочего места |
