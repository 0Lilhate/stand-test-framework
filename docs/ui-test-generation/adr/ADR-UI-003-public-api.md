# ADR-UI-003: Публичный Java API — шаги, локаторы, проверки, захват

**Статус:** Accepted · **Дата:** 2026-08-01 · **Реализован (минимальный срез):** 2026-08-02 · **Волна:** 1

## Контекст

D-4 фиксирует артефактом генерации Java-тест JUnit 5 с Page Object'ами. Значит публичный API — это
не служебная поверхность, а **текст, который читает и ревьюит автоматизатор** и который порождает
агент. NFR-07 требует, чтобы результат проходил линтер потребителя без исключений.

Приложение А BRD даёт иллюстрацию API, но сам BRD помечает её как **не утверждённую**: «точные имена
классов и сигнатуры builder'ов — предмет технического проектирования».

Существующий идиом SDK, проверенный по коду четырёх адаптеров:

- один fluent-класс на адаптер (`RestStep`, `DbStep`, `KafkaStep`, `GrpcStep`);
- статические фабрики выбирают тип шага (`RestStep.get/post/expectEventually`);
- `id(...)`, затем методы по концернам, затем `build()` → `ScenarioStep` (реально `GenericStep`);
- параметры складываются в `Map` под константами `*StepParameters`, которые **зеркалят**
  `StepParameterKeys`;
- ассершены и захваты — иммутабельные `record` (`RestAssertion`, `RestCapture`);
- сравнение делегируется в общий `core.assertion.AssertionMatchers` — так kafka и db уже не дают
  четырём адаптерам разъехаться в семантике равенства.

## Рассматриваемые варианты

**А. Повторить идиом SDK: `UiStep` + `UiLocator` + record-ассершены, оценка через `AssertionMatchers`.**

**Б. Page Object как базовый класс SDK** (`abstract class StandPage` с protected-методами
`click`/`fill`), от которого наследуется Page Object потребителя.

**В. Отдельный API с собственным эвалюатором проверок** (свои матчеры под DOM: `isVisible`,
`hasText`, …), не связанный с `AssertionMatcher`.

**Г. Составные шаги как в иллюстрации BRD** (`UiStep.form(APP).select(...).type(...)`).

**Д. Отдельный класс на каждый тип шага** (`UiOpenStep`, `UiClickStep`, `UiExpectStep`, …).

## Решение

Принимается **вариант А**.

### Публичная поверхность и обоснование каждого типа

| Тип | Почему публичен |
|---|---|
| `UiStep` | Единственная точка входа автора; прямой аналог `RestStep` |
| `UiLocator` | Живёт константами в Page Object потребителя. Без публичности Page Object невозможен, локаторы утекут в тело теста и обесценят митигацию RISK-02 |
| `LocatorStrategy` | Приоритет локаторов (D-5) должен быть выразим и считаем — вход в KPI-9 |
| `UiProperty` | Точка расширения `assertProperty(...)`: новое свойство не требует релиза SDK ради нового метода-сахара |
| `UiCaptureSource` | Захват из `value` поля ввода иначе невыразим |
| `UiDriver`, `UiDriverFactory`, `ElementSnapshot` | **Шов подмены**: даёт unit-тесты без браузера — и нам, и потребителю. Прямой аналог публичного `HttpCaller` |
| `UiApplicationResolver`, `ResolvedUiApplication` | Тот же шов для реестра; аналог публичного `BaseUrlResolver` |
| `UiStepParameters` | Читает `scenario-yaml` (волна 3) и потребитель, разбирающий чужой `GenericStep`; `RestStepParameters` публичен ровно поэтому |
| `UiAssertion`, `UiCapture` | Иммутабельные записи в параметрах шага; читаемы теми же потребителями |

**Не публичны:** `UiSession`, `UiAssertionEvaluator`, весь пакет `…ui.playwright`. `UiStepExecutor`
объявлен `public` по требованию `ServiceLoader`, но выведен из поддерживаемой поверхности словами в
Javadoc (аннотации JetBrains запрещены checkstyle'ом репозитория).

### Пять типов шагов волны 1

`ui.open`, `ui.click`, `ui.fill`, `ui.expect`, `ui.expectEventually`. Больше — не нужно; каждый
лишний тип это строка в JSON Schema (волна 3), ветка в гейтах и случай в классификации отказа.

### Локаторы

Фабрики: `testId`, `role(role, name)`, `label`, `text`, `css`. Приоритет — в этом порядке.
`fragile()` возвращает `true` для всего, кроме `TEST_ID`, и является **единым определением
хрупкости** для отчёта генерации (BR-07) и для статического счётчика KPI-9.

**XPath не имеет фабрики.** Отсутствие фабрики — самый дешёвый запрет: тот же приём, которым в SDK
запрещён литеральный URL («нет параметра, куда его положить»).

`sensitive()` помечает зону для маскирования до снятия артефакта (BR-35; механика — ADR-UI-005).

### Проверки

`UiAssertion(property, attribute, expectedValue, matcher)`; оценка — **через
`AssertionMatchers.matches(...)` ядра**, без собственного эвалюатора.

| Свойство | Матчеры |
|---|---|
| `TEXT`, `VALUE`, `ATTRIBUTE` | EQUALS, CONTAINS, MATCHES, EXISTS, NOT_NULL |
| `VISIBLE`, `ENABLED` | **только EQUALS** |

Ограничение по булевым свойствам проверяется в `build()` (fail-fast при сборке сценария) и повторно
в executor'е. Асимметрия документируется так же явно, как существующая асимметрия «kafka
equals-only против rest/grpc» — необъявленная асимметрия уже была источником путаницы в проекте.

### Захват

`UiCapture(variableName, locator, source, attribute)`; executor кладёт значение в
`context.variableStore()`. Это и есть механизм BR-13 «связывание по данным» — **новых строк в core
не требуется**. Обратное направление (`fill(locator, "${customerName}")`) разрешается через
`context.resolver()`, тем же `VariableResolver`, что и тело REST-запроса.

## Расхождения реализации с ADR (2026-08-02) и их причины

Решение (вариант А) принято без изменений: `UiStep` + `UiLocator` + record-ассершены, оценка через
`AssertionMatchers` ядра, пять типов шагов, отсутствие XPath-фабрики, `fragile()` как единое
определение хрупкости, `UiSession`/`UiAssertionEvaluator`/пакет `playwright` — непубличны. Разошлись
детали поверхности; каждое расхождение — сознательное.

| Что в ADR | Что в коде | Почему |
|---|---|---|
| `UiLocator(strategy, value, accessibleName, sensitive)` + метод `sensitive()` | компонент как в ADR; метод-разметка называется `asSensitive()` | Реализовано **с живым потребителем**: маскируются значения в сообщении об отказе и в диагностике ожидания. Изначально компонент был отложен как «флаг, который никто не читает» (дефект класса `cf81358`), но у него нашёлся потребитель раньше артефактов: ассершен на поле пароля иначе кладёт пароль в отчёт, лог и вывод CI. Имя метода изменено вынужденно — запись уже порождает аксессор `sensitive()`, и два метода с одной сигнатурой невозможны; предикат читается симметрично `fragile()` |
| `UiDriver.captureArtifacts(label, sensitiveZones)`, тип `UiArtifacts` | нет | Приёмника артефактов в этом срезе нет (`Attachment` бинарных вложений — S-2.1). Маскирование **в DOM перед снятием** приходит вместе с ними; разметка для него уже есть |
| `UiDriver.navigate(String)`, `snapshot(locator, probeTimeout)` | `navigate(path, timeout)`, `snapshot(locator, attributes, probeTimeout)`, плюс `currentUrl()` | Таймаут навигации обязан быть ограничен так же, как остальные. Список атрибутов передаётся явно, потому что драйвер иначе либо читает весь DOM-атрибутный набор, либо не может ответить на `assertAttribute`. `currentUrl()` нужен диагностике шага (`ui.url`) |
| Тип `UiAction(kind, locator, value)` в составе модуля | нет | Действие полностью выражено типом шага и параметрами; отдельная запись ничего не добавляла бы, а поверхность увеличивала |
| Публичных типов исключений не предполагалось | добавлен `UiElementNotActionableException` | Классификация «элемент не стал actionable → FAILED, всё прочее → BROKEN» проходит **через публичный шов** `UiDriver`. Без публичного типа сторонняя реализация драйвера не может её выразить, и таблица §10.1 превратилась бы в договорённость на словах |
| `UiRunSettings` перечислен среди «исполнения», без явного статуса | публичен | Это и есть контракт headed/headless и таймаутов (BR-18/BR-19); потребитель настраивает прогон через него |
| `capture(variableName, from, source)` покрывает и атрибут | добавлена перегрузка `captureAttribute(variableName, from, attribute)` | Захват атрибута требует двух параметров; трёхаргументная форма их не выражает |
| `UiStep.open(...).assertVisible()` в примере §4.6 | ассершены на `ui.open`/`ui.click`/`ui.fill` **запрещены** в `build()` | У `ui.open` нет локатора — проверять было бы нечего; у действий проверка отняла бы собственный номер шага в отчёте. Это то же соображение, которым в §«Отклонённые альтернативы» отвергнут составной `UiStep.form`. Пример в §4.6 исправлять не стали — он помечен здесь |
| `injectCorrelationId()` без указания заголовка | заголовок — **package-private** константа `X-Correlation-Id`, имя задокументировано в README модуля | У UI-приложения в реестре нет секции `correlation` (в отличие от REST-сервиса), поэтому имя брать неоткуда. Публичной константу не делаем: она жила бы на классе, выведенном из поддерживаемой поверхности. Флаг применяется на каждом шаге, который его просит, а не только на открывающем сессию — иначе `injectCorrelationId()` на втором шаге был бы тихим no-op |
| `description(...)` в билдере | есть | Совпадает; `GenericStep` несёт `description` |

## Последствия

**Положительные.**
Автоматизатор, знающий `RestStep`/`DbStep`, читает `UiStep` без обучения. Агент генерирует UI-тест
той же грамматикой, что протокольный, — расширение кита получается инкрементом скилла, а не новым
треком. Делегирование в `AssertionMatchers` не даёт пятому адаптеру разъехаться с четырьмя.
Публичные швы `UiDriver`/`UiApplicationResolver` дают ~70 % тестов модуля без браузера.

**Отрицательные.**
`UiDriver` в публичном API — обязательство совместимости на интерфейс, который в волне 2–3 захочет
расти (перехват сети BR-33, скриншот-сравнение BR-14). Митигация: методы добавляются как `default`
с реализацией «не поддерживается», как это принято для `StepExecutor.prepare`.

Пять типов шагов означают, что «заполнить форму из семи полей» — это семь шагов в отчёте. Это
сознательный выбор в пользу диагностики.

**Нейтральные.**
Расхождения с иллюстрацией BRD перечислены в [`10-target-architecture.md`](../10-target-architecture.md)
§4.7 и не являются отступлением от требований: иллюстрация не утверждена.

## Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Агент размажет локаторы по телу теста вместо Page Object | **Высокая** | Среднее | Детектор гейта «объявление `UiLocator` вне класса-Page Object»; правило в скилле авторинга; проверка на эталонном наборе |
| `css(...)` станет путём наименьшего сопротивления и утопит KPI-9 | Средняя | Среднее | `fragile()` считается статически; KPI-9 >50 % — триггер эскалации (D-5); отчёт генерации перечисляет хрупкие локаторы |
| `UiDriver` придётся ломать в волне 2 | Средняя | Среднее | Новые методы — `default`; аддитивное расширение |
| Ограничение «булево — только EQUALS» воспримут как баг | Средняя | Низкое | Fail-fast в `build()` с внятным сообщением; документируется рядом с kafka-асимметрией |
| API окажется неудобным на реальном приложении волны 1 | Средняя | Среднее | Slice 5 (агентная генерация) — первая честная проверка; API до неё считается непубличным де-факто |

## Отклонённые альтернативы

**Б — Page Object как базовый класс SDK.** Отклонено. Наследование навязывает потребителю иерархию,
конфликтует с его собственными базовыми классами, мешает статическим фабричным методам (стиль
Приложения А, который здесь как раз удачен) и делает Page Object невозможным без зависимости на SDK
в compile-scope продуктового кода. Композиция через публичный `UiLocator` даёт то же самое без
связывания.

**В — собственный эвалюатор проверок.** Отклонено. Это пятая копия логики сравнения. Проект уже
проходил через это: kafka и db **специально** переведены на `AssertionMatchers.equalsMatch`, чтобы
адаптеры не разъезжались. Заводить расхождение обратно ради «DOM-специфичности» неоправданно:
`CONTAINS`/`MATCHES` над строкой одинаковы и для JSON-поля, и для текста элемента.

**Г — составные шаги (`UiStep.form`).** Отклонено. Даёт вторую грамматику для того же действия,
усложняет JSON Schema волны 3 и **прячет номер шага в отчёте**: при падении на третьем поле метка
`Step [3/7] 'fill-amount' (ui.fill)` точнее, чем `Step [2/5] 'fill-form' (ui.form)`. Диагностика
дороже краткости — это же соображение стоит за D-7.

**Д — класс на каждый тип шага.** Отклонено: расходится с идиомом всех четырёх существующих
адаптеров и удваивает поверхность без выигрыша.

## Требования BRD, которые закрывает ADR

`BR-06` (Java-тест на публичном API с Page Object'ами), `BR-10`/`BR-11` (позитивный путь и валидации
форм), `BR-13`/`D-8` (связывание по захваченным данным), `BR-23` (`within`/`pollInterval` только на
`expectEventually`), `BR-27` (нет параметра под URL), `BR-35` (`sensitive()`), `D-4`, `D-5`
(приоритет локаторов и `fragile()`), `NFR-07`.

| Тест | Уровень | Что доказывает | Состояние |
|---|---|---|---|
| `factoriesProduceTheirOwnTypes` | unit | Каждая фабрика даёт свой `type`, параметры под ключами `UiStepParameters` | ✅ (имя уточнено) |
| `booleanPropertyRejectsNonEqualsMatcher` | unit | `assertProperty(VISIBLE, CONTAINS, …)` падает при сборке шага | ✅ |
| `expectRequiresAtLeastOneAssertion` | unit | По образцу `RestStep.build()`, для обоих проверяющих типов | ✅ |
| `withinIsRejectedOnNonPollingStep` | unit | `within(...)` на `ui.click` — `IllegalStateException` | ✅ |
| `noParameterAcceptsAbsoluteUrl` | unit | Ни одна публичная сигнатура не принимает абсолютный адрес | ✅ |
| `noXPathFactoryExists` | unit | Ни фабрики, ни константы стратегии, ни публичного метода с «xpath» в имени | ✅ |
| `fragileIsFalseOnlyForTestId` | unit | Единое определение хрупкости | ✅ |
| `evaluatorDelegatesToCoreMatchers` | unit | Вердикт адаптера **совпадает** с `AssertionMatchers.matches` на каждом матчере | ✅ |
| `captureLandsInVariableStore` | unit (фейковый драйвер) | Захват доступен последующему шагу как `${var}`; то же на реальном браузере — `capturedValueIsVisibleToTheNextStep` | ✅ |
