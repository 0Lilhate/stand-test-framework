## D-01 · ADR-UI-005 — форма бинарных вложений

| | |
|---|---|
| **ID** | D-01 · документ [`adr/ADR-UI-005-reporting-and-artifacts.md`](../adr/ADR-UI-005-reporting-and-artifacts.md) |
| **Название** | Отчётность, артефакты падения и маскирование |
| **Статус** | `ACCEPTED 2026-08-04` · **принят вариант А** и реализован: `record Attachment(String name, String mediaType, String content, Path file)` с инвариантом «ровно одно из `content`/`file` не null» |
| **Причина** | *(состояние на момент постановки, 2026-08-03; решение с тех пор принято — см. строку «Статус»)* `core/event/Attachment.java` — `record Attachment(String name, String mediaType, String content)`; `DefaultAllureLifecycleFacade:67` делает `content.getBytes(UTF_8)`. Тракт вложений текстовый целиком: PNG, WebM и ZIP не проходят. Base64 в текстовое поле не решает — `AttachmentType.extensionForMediaType()` выдаст `.bin`. **Это изменение `core`, не учтённое в §13.1 BRD**: там как правка core названы только компенсации (D-9) |
| **Варианты** | **А.** компонент `Path file` в `Attachment`, инвариант «ровно одно из `content`/`file` не null» · **Б.** компонент `byte[] binaryContent` · **В.** отдельный record `BinaryAttachment` + второй список в `StepResult`/`StepEvent` · **Г.** путь к файлу текстом в `content` с условленным media type · **Д.** артефакты не проходят через отчёт вовсе — каталог прогона + пути в диагностике |
| **Рекомендация** | **А** (позиция черновика ADR) — **это и принято**: аддитивно, `new Attachment(a,b,c)` и `of(...)` компилируются без правок; `Path`, в отличие от `byte[]`, корректен в `equals`/`hashCode` record'а, чего требуют правила репозитория об иммутабельных value-типах |
| **Последствия** | **А:** правка стока графа, от которого зависят все 14 модулей → RISK-15, обязательный прогон 1484 тестов · **Б:** ломает `equals`/`hashCode` record'а и правило иммутабельности · **В:** дублирует список вложений в двух контрактах, дрейф гарантирован · **Г:** тип-небезопасно, приёмник обязан догадываться · **Д:** BR-21 формально закрывается, но отчёт остаётся без картинки — падение диагностируется вне Allure |
| **Зависимые задачи** | ~~S-2.1 (`BLOCKED`), S-2.2, S-2.3, N-07~~ — **весь срез артефактов реализован**: `UITG-S012`/`T001`…`T003` (канал вложений), `S013`…`S018` (скриншот, консоль, сеть, трейс, маскирование, ретенция); косвенно KPI-7 |

| **Причина** | D-9 BRD утверждает, что откат UI-данных требует доработки `core`. | | |
|---|---|
| **ID** | D-04 · документ [`adr/ADR-UI-008-starter-executor-discovery.md`](../adr/ADR-UI-008-starter-executor-discovery.md) |
| **Название** | Подъём `UiStepExecutor` на Spring-пути |
| **Статус** | `ACCEPTED 2026-08-08` · **вариант Б** — стартер добирает исполнителей `ServiceLoader`'ом в дополнение к бинам; бин всегда побеждает SPI, правило общее (не UI-специальное), подбор объявляется одной строкой `INFO`. Арх-правило `nothingDependsOnUi` **не менялось** |

На plain-JUnit проблемы нет: `StandTestExtension:170` берёт исполнителей через `ServiceLoader` |

| **Рекомендация** | **Б** — **принято 2026-08-08 ровно так**: не трогает arch-правило (компиляционного ребра не возникает), убирает ручной шаг у потребителя и подхватит любой будущий сторонний адаптер. Требует дедупликации «бин + SPI одного типа», и приоритет задан явно: **бин сильнее SPI** |
| **Последствия** | **А:** ослабляет правило, которое защищает протокольные тесты от браузера в classpath · **Б:** порядок исполнителей становится менее явным; нужен тест на дедупликацию · **В:** ~~нулевая стоимость сейчас~~ — **проверено 2026-08-08 и неверно: обход НЕ документирован нигде** (ни README стартера, ни корневой, ни исходники), поэтому В означал бы сначала написать недостающий раздел; плюс постоянный налог на каждого Spring-потребителя |

## D-07 · ADR-UI-011 — стратегия измерения набора: браузерный дубль или живой стенд

| | |
|---|---|
| **ID** | D-07 |
| **Название** | Как эталонный набор становится прогоняемым |
| **Статус** | `ACCEPTED 2026-08-06` · **выбран вариант А** — DOM локального приложения сводится к DOM UI-кейсов. Решение оформлено в [`adr/ADR-UI-011-browser-duplicate-measurement.md`](../adr/ADR-UI-011-browser-duplicate-measurement.md) |
| **Причина** | PQ-09 / GAP-06. У всех 12 UI-кейсов `execution.outcome: NOT_RUN`: браузерного дубля набор не поставляет. **Уточнение spike:** до браузера доходят **4 кейса из 12** — остальные восемь по замыслу заканчиваются на `AWAITING_APPROVAL` раньше, чем понадобится DOM, и их `NOT_RUN` верная запись, а не долг. Область сближения — **два экрана и одиннадцать элементов**. Кандидат существует — `stand-test-ui/src/test/java/.../playwright/LocalUiTestApplication.java` (тот же алиас `client-portal`, форма входа, сессионная кука, асинхронный статус), но **его DOM другой**. Шесть UI-кейсов получают отчёт разведки готовым, то есть набор измеряет авторинг, а не разведку |
| **Варианты** | **А.** привести `LocalUiTestApplication` к DOM кейсов · **Б.** привести кейсы к DOM существующего приложения · **В.** написать отдельный дубль под набор · **Г.** мерить только на живом стенде (тогда набор ждёт G-1/G-4/G-5) |
| **Рекомендация** | **А** — spike выполнен и ответил ([`31-ui-dom-convergence-spike.md`](31-ui-dom-convergence-spike.md) §6). Решает не объём правок (по строкам Б даже дешевле: ~170 против ~200 + ~200 тестов), а то, что **три кейса непереносимы** — `ui-fragile-locators-no-testid`, `ui-form-validation-…`, `ui-non-reversible-bulk-delete` написаны про свойство DOM, которого у дубля нет по построению, и ещё два обедняются. **Г** отдельно по-прежнему не годится: ставит измеримость кита в зависимость от внешних гейтов. Строка «выбирать до spike нельзя» снята — она относилась к состоянию до 2026-08-04 |
| **Последствия** | **А:** дубль растёт вместе с набором, и это не главная его цена — spike измерил скрытую: дубль, совпавший с шестью подсаженными отчётами разведки, обязан совпадать с ними и дальше, иначе корпус воспроизведёт дефект собственного кейса `ui-stale-discovery-testid-renamed`. Отсюда обязательный тест-парити · **Б:** кейсы теряют фактуру, ради которой писались · **В:** третий DOM в репозитории · **Г:** KPI-3/KPI-4 не наблюдаются до пилота. **Общее для А–В:** результат на дубле — **не** замер на живом приложении, и это обязано быть написано рядом с числом |
| **Зависимые задачи** | N-03 (`BLOCKED`), M-01 частично |
| **Требования** | KPI-3, KPI-4, измеримость BR-01/BR-05/BR-10/BR-11 |
| **Владелец решения** | команда SDK |
| **Срок** | до замеров §19.1 |

## D-08 · ADR-UI-012 — параллельность: классы или классы + методы

| | |
|---|---|
| **ID** | D-08 |
| **Название** | Модель параллельности UI-набора |
| **Статус** | `REQUIRED` — конфликт зафиксирован, решения нет |
