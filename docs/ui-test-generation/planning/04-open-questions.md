| | |
|---|---|
| **Документ** | Реестр вопросов, требующих решения до реализации |
| **Дата** | 2026-08-03 |
| **Отношение к существующим реестрам** | BRD §20 (OQ-01…OQ-13) и [`../02-open-questions.md`](../02-open-questions.md) (Q-01…Q-15) — **источники**; этот файл их сводит, добавляет вопросы, возникшие при инвентаризации, и для каждого называет блокируемое решение |

## 1. Вопросы, блокирующие планирование

### PQ-01. В какой форме бинарные артефакты попадают в отчёт?

| | |
|---|---|
| **Источник** | `../02-open-questions.md` Q-01 · CONF-09 · ADR-UI-005 (Proposed) |
| **Суть** | `core/event/Attachment.java:26` — `record Attachment(String name, String mediaType, String content)`. Скриншот, видео и трейс не проходят. Варианты: добавить бинарный компонент в `Attachment`; передавать путь к файлу вместо содержимого; вынести артефакты из событийного канала целиком |
| **Что блокирует** | планирование BR-21, BR-22 (часть «слой + артефакты»), BR-35, SEC-05, SEC-09; косвенно KPI-7 |
| **Владелец ответа** | команда SDK |
| **Срок** | до планирования волны 1 |
| **Временный workaround** | частично: красный прогон уже даёт `scenarioId`/`testRunId`/`correlationId`, номер и тип шага в тексте исключения и в MDC |
| **Начальный статус** | `DECISION` |

### PQ-02. Компенсатор адаптера или сценарный cleanup-шаг?

| | |
|---|---|
| **Источник** | `../02-open-questions.md` Q-02 · D-9 · ADR-UI-007 (Proposed) · RISK-15 |
| **Суть** | сегодня `undoLog().register(...)` вызывает только `DbStepExecutor:191`. Для UI нужно решить: регистрирует ли компенсацию сам UI-исполнитель (как БД), или в сценарии появляется явный cleanup-шаг, или откат делается backend-вызовом |

## 2. Вопросы, блокирующие реализацию (но не план)

### PQ-05. Что делать с правилом `nothingDependsOnUi` и Spring-стартером?

| | |
|---|---|
| **Источник** | CONF-04 · GAP-10 (обнаружено этой инвентаризацией) |
| **Суть** | arch-тест запрещает любому модулю SDK ссылаться на `ui`. Стартер собирает раннер из бинов `StepExecutor` и объявляет их поимённо; бина UI нет. Варианты: исключение из правила; добор `ServiceLoader`'ом в стартере; оставить ручное объявление и задокументировать |
| **Что блокирует** | адоптацию у Spring-потребителей |
| **Владелец ответа** | команда SDK |
| **Срок** | до первого Spring-потребителя UI |
| **Временный workaround** | да: потребитель объявляет `@Bean UiStepExecutor` сам |
| **Начальный статус** | `DECISION` |

## 5. Чего в этом реестре намеренно нет

- **Сроков и исполнителей.** Их назначает команда; выдумывать их здесь означало бы выдать
  предположение за план.
- **Оценок трудоёмкости.** Инвентаризация фиксирует объём неизвестного, а не стоимость работы.
- **Ответов.** Ни один вопрос выше не закрыт этой работой; закрытые вопросы отмечены в источниках
  (например, Q-15 частично закрыт 2026-08-03).
